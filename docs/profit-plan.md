# 獲利計畫書

## 一、策略定位

| 項目 | 內容 |
|------|------|
| 策略類型 | 台股現股當沖 |
| 持倉時間 | 盤中（09:00~13:30），不留隔夜 |
| 標的篩選 | 權值股 / 中大型股（成交量充足） |
| 進場方式 | 開盤後追漲（1%~5% 漲幅帶） |
| 出場方式 | 移動停利 / 固定停損 / 收盤強制清倉 |

## 二、資金配置

### 2.1 建議起始資金

| 等級 | 總資金 (MAX_FUND) | 每檔張數 | 適用情境 |
|------|-------------------|----------|----------|
| 保守 | 200,000 | 1 | 初期測試、驗證策略 |
| 標準 | 500,000 | 2 | 策略驗證後正式運行 |
| 積極 | 1,000,000 | 3 | 策略穩定且有足夠經驗 |

### 2.2 資金分配原則

- **單檔不超過總資金 40%**: 假設 MAX_FUND = 500,000，單檔最多投入 200,000
- **MAX_LOT_PER_SYMBOL 控制張數**: 配合上述原則調整
- **保留足夠現金**: 確保帳戶淨值始終大於當日最大可能虧損

### 2.3 保證金需求（現股當沖）

台股現股當沖需要先有足夠的交割款或信用額度：
- 買進：T+2 交割（但當沖當天沖銷則不需實際交割）
- 確保帳戶有足夠的交割準備金，以防因策略異常未能當日平倉

## 三、風險控管

### 3.1 單筆風控

| 風控項目 | 預設值 | 最大可能損失 |
|----------|--------|-------------|
| 停損百分比 | -3% | 單筆虧損上限 |
| 每檔張數 | 2 張 | 限制單筆曝險 |

**單筆最大虧損計算**:
```
單筆最大虧損 = 股價 * 1000 * 張數 * |停損百分比|

範例: 股價 500 元、2 張、停損 -3%
= 500 * 1000 * 2 * 0.03
= 30,000 元
```

### 3.2 每日風控

| 風控項目 | 設計 |
|----------|------|
| 防重複送單 | `_enter_placed` 防止同一檔重複委託；平倉後清除。若 `ALLOW_SAME_DAY_REENTRY=true`（ConfigurableStrategy），可回落買回再進 |
| 總資金上限 | `MAX_FUND` 限制當日最大曝險 |
| 全出場時間 | `EXIT_TIME` (13:15) 確保不留部位 |

**每日最大理論虧損**:
```
最大虧損 = MAX_FUND * |停損百分比|

範例: MAX_FUND = 500,000、停損 = -3%
= 500,000 * 0.03
= 15,000 元
```

### 3.3 停損/停利參數調整建議

| 情境 | STOP_LOSS_PCT | TAKE_PROFIT_PCT | TRAILING_STOP_PCT |
|------|---------------|-----------------|-------------------|
| 保守 | -2.0 | 4.0 | 1.5 |
| 標準 | -3.0 | 6.0 | 2.0 |
| 積極 | -5.0 | 8.0 | 3.0 |

**原則**:
- 停損越小，虧損越有限，但也容易被「洗掉」（正常波動觸發停損）
- 停利門檻越高，獲利才會啟動追蹤，但可能等不到（策略不觸發）
- 回撤閾值越大，給更多空間讓股價「喘息」，但也可能把利潤吐回去

## 四、交易成本

### 4.1 費用結構

| 費用項目 | 費率 | 說明 |
|----------|------|------|
| 買入手續費 | 0.1425% | 券商可能打折 (常見 28 折 ≈ 0.04%) |
| 賣出手續費 | 0.1425% | 同上 |
| 證交稅 | 0.15% | 當沖交易減半（一般 0.3%） |

### 4.2 成本計算範例

假設手續費 28 折（0.04%）：
```
買入: 100 元 * 1000 股 * 2 張 = 200,000 元
  手續費: 200,000 * 0.04% = 80 元

賣出: 103 元 * 1000 股 * 2 張 = 206,000 元
  手續費: 206,000 * 0.04% = 82 元
  證交稅: 206,000 * 0.15% = 309 元

總成本: 80 + 82 + 309 = 471 元
毛利: 206,000 - 200,000 = 6,000 元
淨利: 6,000 - 471 = 5,529 元
```

### 4.3 損益平衡

以 28 折手續費、當沖證交稅為準：
```
損益平衡漲幅 ≈ 買入手續費率 + 賣出手續費率 + 證交稅率
            = 0.04% + 0.04% + 0.15%
            = 0.23%
```

漲幅超過 0.23% 才開始獲利。

## 五、預期績效分析

### 5.1 情境模擬

以下基於不同勝率與盈虧比的假設，估算每月預期損益：

**假設條件**:
- 每日平均交易 1~2 次
- 每月交易日 22 天
- 平均投入金額 300,000 / 筆
- 手續費 28 折 + 當沖證交稅

**情境 A -- 保守估計（勝率 40%，盈虧比 2:1）**

| 項目 | 值 |
|------|-----|
| 月交易次數 | 30 |
| 勝率 | 40% |
| 平均獲利 | +2.0% (≈6,000) |
| 平均虧損 | -1.0% (≈3,000) |
| 月交易成本 | ≈ 30 * 471 = 14,130 |
| 月毛利 | 12 * 6,000 - 18 * 3,000 = 18,000 |
| 月淨利 | 18,000 - 14,130 ≈ 3,870 |

**情境 B -- 標準預期（勝率 45%，盈虧比 2:1）**

| 項目 | 值 |
|------|-----|
| 月交易次數 | 30 |
| 勝率 | 45% |
| 平均獲利 | +3.0% (≈9,000) |
| 平均虧損 | -1.5% (≈4,500) |
| 月交易成本 | ≈ 14,130 |
| 月毛利 | 13.5 * 9,000 - 16.5 * 4,500 = 47,250 |
| 月淨利 | 47,250 - 14,130 ≈ 33,120 |

**情境 C -- 理想表現（勝率 50%，盈虧比 2.5:1）**

| 項目 | 值 |
|------|-----|
| 月交易次數 | 30 |
| 勝率 | 50% |
| 平均獲利 | +4.0% (≈12,000) |
| 平均虧損 | -1.6% (≈4,800) |
| 月交易成本 | ≈ 14,130 |
| 月毛利 | 15 * 12,000 - 15 * 4,800 = 108,000 |
| 月淨利 | 108,000 - 14,130 ≈ 93,870 |

### 5.2 關鍵指標

| 指標 | 定義 | 建議目標 |
|------|------|----------|
| 勝率 | 獲利筆數 / 總筆數 | > 40% |
| 盈虧比 | 平均獲利 / 平均虧損 | > 1.5 |
| 期望值 | 勝率 * 平均獲利 - (1-勝率) * 平均虧損 | > 0 |
| 最大回撤 | 資金曲線從高點到低點的最大跌幅 | < 15% 總資金 |
| Sharpe Ratio | (策略報酬 - 無風險利率) / 報酬標準差 | > 1.0 |

### 5.3 期望值公式

```
期望值 = 勝率 * 平均獲利 - (1 - 勝率) * 平均虧損 - 交易成本

範例 (標準預期):
= 0.45 * 9,000 - 0.55 * 4,500 - 471
= 4,050 - 2,475 - 471
= 1,104 元 / 筆
```

只要每筆期望值 > 0，長期交易下去就會是正報酬。

## 六、策略調整路線圖

### Phase 1 -- 驗證期（1~2 個月）

- 使用模擬模式 (`SIMULATION=true`)
- 記錄所有交易，分析勝率與盈虧比
- 目標：確認策略期望值 > 0

### Phase 2 -- 小額實單期（1~2 個月）

- `MAX_FUND = 200,000`、`MAX_LOT_PER_SYMBOL = 1`
- 確認實單滑價、成交速度等與模擬的差異
- 目標：月報酬率 > 0

### Phase 3 -- 標準運行期

- 根據 Phase 2 的數據調整參數
- 逐步放大 `MAX_FUND`
- 持續監控最大回撤，超過 15% 暫停檢討

### Phase 4 -- 策略迭代

- 增加進場篩選條件（成交量、技術指標）
- 增加多策略輪換 / 組合
- 引入回測框架驗證新邏輯

## 七、風險警示

1. **過去表現不代表未來績效**: 回測或模擬的獲利在實際市場中可能無法複製
2. **滑價風險**: 市價單成交價可能劣於預期，特別是流動性差的標的
3. **系統風險**: 斷線、程式異常可能導致無法及時出場
4. **政策風險**: 台股當沖制度、證交稅率可能調整
5. **黑天鵝事件**: 極端行情下（如跌停鎖死）可能無法賣出
6. **此策略不構成投資建議**: 僅為技術實作參考，使用者需自行承擔風險
