# 期貨為輔、現貨為主：AI 自動化交易策略架構

> **台指期正逆價差** = 期貨價 − 現貨價。正價差（期 > 現）表示情緒偏熱；逆價差（期 < 現）表示情緒偏保守。亦稱「期現貨價差」。術語詳見 [glossary.md](glossary.md)。

> **定位**：本文件是一份**策略規劃與方法論**，不是已實作的程式。
> 核心觀念是 **放棄高風險的期貨短線肉搏，把期貨轉化為股票現貨投資的「領先指標儀表板」**。
>
> 本專案目前的自動下單能力僅限**台股現股**（見 [trading-rules.md](trading-rules.md)）；
> 期貨、選擇權目前**未實作下單**（見 README「可以買賣的市場與限制」）。
> 以下策略中的「期貨數據」皆作為**輔助判斷/訊號來源**，最終下單標的仍為現貨股票 / ETF。

## 第一部分：期貨與股票現貨 QA 精華整理

### 核心現象解析：為何台指期「盤前跌、開盤漲」？

| # | 階段 | 現象 | 解讀 |
|---|------|------|------|
| 1 | 08:45 期貨開盤 | 先反映昨晚美股跌幅 | **反映美股利空** |
| 2 | 08:45 ~ 09:00 | 散戶停損 + 程式單壓低指數 | **恐慌宣洩** |
| 3 | 09:00 現貨開盤 | 龐大資金與內資湧入撿便宜，帶動期貨「校正回歸」 | **現貨護盤拉升** |
| 4 | 09:00 之後 | 主力刻意壓低洗出多單、誘騙空單後再拉抬現貨「軋空」 | **主力洗盤誘空** |

### 工具屬性對比

| 比較項目 | 台指期貨 (短線投機) | 股票 / ETF (波段投資) |
|----------|---------------------|------------------------|
| **交易邏輯** | 預測大盤指數漲跌 (零和博弈) | 買入企業所有權，與產業共同成長 |
| **資金需求** | 僅需保證金 (具高槓桿、斷頭風險) | 需支付全額交割款 (風險可控) |
| **操作難度** | 需極強心理素質、鐵血停損紀律 | 需耐心、資金控管、逢低佈局的勇氣 |

### 4 大期貨觀察指標（輔助股票交易）

| 指標 | 觀察時點 | 解讀與行動 |
|------|----------|-----------|
| **開盤溫度計** | 08:45 | 若期貨開盤重挫且持續破底 → 暗示 09:00 股票將面臨沉重賣壓，宜暫緩早盤買進，待 09:30 後伺機而動 |
| **夜盤收盤價** | 清晨 05:00 | 提前消化美股漲跌；若夜盤大跌可預判台股開盤低點，避免恐慌性拋售 |
| **外資未平倉量** | 每日 15:30 公告 | 判斷波段趨勢：淨多單增加代表看好後市；淨空單達數萬口需提防外資在現貨倒貨 |
| **正逆價差** | 盤中 | 正價差＝情緒樂觀過熱；逆價差＝情緒悲觀保守（需扣除 6–8 月除權息蒸發點數）|

## 第二部分：AI 自動化交易策略推薦

基於「期貨籌碼與數據為輔助判斷」的邏輯，透過 Python 自動化腳本，
並結合本地端硬體算力（如高階顯卡）執行 AI 模型推論。推薦三套策略：

### 策略一：夜盤跳空與早盤情緒捕捉（量化條件單）

將「開盤溫度計」完全自動化，鎖定中長線 ETF 或電子權值股的逢低買點。

- **數據收集層**：透過開源 API（如富果 Fugle 或永豐 Shioaji）自動抓取
  - 前一日台指夜盤收盤價
  - 08:45 ~ 08:59 的期貨即時跳動數據
- **AI 邏輯判定**（兩條件同時成立）：
  1. 夜盤跌幅 > 1%（反映美股利空）
  2. 08:45 ~ 08:55 期貨跌幅沒有繼續擴大，甚至出現微幅拉升（主力洗盤結束跡象）
- **自動執行**：09:00 現貨開盤時，程式自動觸發委託單，分批買入追蹤半導體或電子零組件產業的優質 ETF。

### 策略二：外資籌碼與大盤趨勢防禦網（機器學習預測）

利用外資未平倉量與價差數據，建立趨勢預警系統，動態調整持股水位。

- **數據收集層**：每日 15:30 爬取期交所公告的
  - 外資期貨未平倉多空淨額
  - 前十大交易人籌碼
  - 期現貨價差
- **AI 分析層**：以過去 5 年的籌碼數據與台股大盤走勢為訓練集，透過機器學習套件
  （Scikit-learn 隨機森林 / XGBoost）訓練模型，預測未來一週的下行風險機率。
- **自動執行**：若 AI 預測下行風險超過警戒值（例如外資空單異常暴增），程式自動
  - 發送 Telegram / Discord 通知，或
  - 自動賣出部分股票部位以保留現金。

### 策略三：本地 LLM 新聞情緒分析（非結構化數據整合）

將市場的文字消息轉化為可量化的交易訊號，避免被市場氣氛帶著走。

- **數據收集層**：定時爬取國內外財經新聞網頁、PTT 股版或相關論壇的熱門文章。
- **AI 分析層**：透過本地端部署的開源 LLM（如以 Ollama 載入 Llama 3 或 Mistral），
  對文本進行情緒分析（Sentiment Analysis），評分 1–10 分（極度悲觀到極度樂觀）。
- **綜合判定**：當 LLM 判定市場情緒為「極度悲觀」，但「期現貨逆價差」卻沒有持續擴大時，
  通常是底部的背離訊號，此時程式可自動篩選基本面優良的標的進入觀察名單。

## 與現有系統的對應與落地路徑

| 策略環節 | 本專案現況 | 銜接方式 |
|----------|-----------|----------|
| 現股 / ETF 自動下單 | 已實作（Shioaji，現股當沖） | 直接沿用 `bot/broker.py` + `RiskGuard` 風控 |
| 主動式 ETF 跟單 | 已實作（28+ 檔快照、共識計算） | 策略一的買入標的可優先取自跟單共識名單 |
| LLM 情緒 / 文本分析 | 已實作（Gemini，法說會分析） | 策略三可改接本地 Ollama，或沿用 `prompts/*.yaml` 版本化管理 |
| 籌碼面拉取 | 已實作（TWSE OpenAPI 三大法人/借券/融資） | 策略二的外資籌碼可擴充至**期交所**期貨未平倉 |
| **台指期正逆價差** | **已實作**（期交所 `DailyMarketReportFut` → `market_macro.FuturesBasis`） | 已併入 macro snapshot，並寫進 `intraday_brief` / `next_day_radar` / `next_day_brief` / `daily_brief` 的盤勢判斷 |
| 外資期貨未平倉量 | **未實作** | 待接期交所三大法人各契約 OpenAPI (指標三) |
| 期貨夜盤 / 即時跳動 | **未實作** | 需新增 Fugle/Shioaji 期貨行情來源 (開盤溫度計即時化) |
| Telegram 通知 | 已實作 | 策略二的風險警示可直接複用 `notifier.py` |

> 風控提醒：任何自動賣出 / 自動進場都應走 `RiskGuard.check_entry()` 與 Kill Switch 機制
> （見 README「資金/風險控制」），確保 12 道閘門全部通過才送單。

> 資料源清單與健康度驗證見 **[data-sources.md](data-sources.md)**（含每個資料源 URL、用途、是否需憑證、失敗 fallback）。
> 「正逆價差」已作為**期貨領先指標**整合進當沖與投資分析的 LLM prompts。

## 建置順序建議（基礎建設優先）

建立系統初期，基礎建設最重要。建議起手環節二擇一：

1. **先測試券商 API 串接**（富果 / Shioaji 期貨行情）
   - 適合：想先把「開盤溫度計、夜盤收盤價」這類**結構化數據**接通，落地最快（策略一/二）。
2. **先在本地端部署 LLM 情緒分析模型**（Ollama + Llama 3 / Mistral）
   - 適合：想先驗證**非結構化文本訊號**的價值，與現有 Gemini 法說分析互補（策略三）。

> 建議：若以「最短路徑產出可下單訊號」為目標，**先從券商 API 串接 + 策略一** 著手；
> 若以「強化判讀深度」為目標，**先部署本地 LLM + 策略三**。
